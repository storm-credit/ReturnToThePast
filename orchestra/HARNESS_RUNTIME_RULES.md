# 하네스 런타임 규칙

이 문서는 RTTP 엔진이 실제로 돌 때 무엇을 순서대로 지키는지 잠근다.

전문가 고용 기준은 `REQUIRED_EXPERT_LOCK.md`를 우선 참조한다.

## 1. 실행 시작 규칙

모든 pass는 아래 순서로 시작한다.

1. 병목 한 줄 정의
2. 현재 작업 / 다음 작업 / 실행 방식 고지
3. 대상 하네스 선택
4. 총괄 단독 여부 판정
5. 필요 시 전문가 고용

단, `필수 전문가 잠금`에 적힌 하네스 기본 전문가는 총괄이 의도적으로 생략하지 않는 한 기본 호출 후보로 본다.

기본 훅 이름은 아래처럼 고정한다.

- `preflight`: 병목, 하네스, no-touch, required reads 잠금
- `dispatch`: 전문가/모델 선택
- `merge`: findings 충돌 정리와 반영 후보 선정
- `verify`: 관련 하네스와 smoke 재실행
- `checkpoint`: session state, 브랜치, 커밋 기준 재확인

금지 표면어와 패킷 기준은 각각 `../Guidelines/Banned_Surface_Ledger.md`, `Packet_Baseline_Register.md`를 런타임 보조 장부로 본다.

자세한 훅 설명은 [HOOK_CATALOG.md](HOOK_CATALOG.md), 하네스별 조합은 [HARNESS_HOOK_MATRIX.md](HARNESS_HOOK_MATRIX.md)를 따른다.

## 2. 동시성 규칙

- 같은 파일에 두 lane을 동시에 쓰지 않는다.
- 좁은 전문가가 findings를 낸 뒤 총괄이 병합 순서를 정한다.
- 병합 전에 스트레스 테스트 lane을 추가할 수는 있어도, 병합 권한은 이동하지 않는다.

## 3. 파일 권한 규칙

- 캐논 파일 최종 수정은 총괄 승인 후에만 유효하다.
- 초안 메모, 시트, 감사 보고서는 전문가가 직접 만들 수 있다.
- 핵심 기준 문서 수정은 총괄 직접 또는 총괄 검토 후에만 반영한다.

## 4. 체크포인트 규칙

- self-contained pass 단위로만 커밋한다.
- 관련 하네스가 한 번이라도 돌아간 뒤에만 체크포인트 후보가 된다.
- `Smoke PASS`는 기본 조건이지 충분조건이 아니다.
- 집필 화는 **공백 제외 3,500자 이상**을 만족해야만 하네스 입력으로 인정한다.
- 분량 미달 화는 즉시 `rewrite required` 상태로 내리고, 다음 하네스로 넘기지 않는다.
- 분량 미달 화가 포함된 배치는 커밋/푸시 후보가 될 수 없다.

## 5. 집필 전환 규칙

다음이 잠기기 전엔 집필 레인을 대량 개방하지 않는다.

- 시간법칙
- 대가 문법
- 적대축
- 마법/몬스터 실전층
- 복선/고정점/엔딩 수렴
- 스모크 감사 PASS

## 6. 실패 처리 규칙

- 전문가 결과가 충돌하면 즉시 총괄 병합 단계로 올린다.
- 하네스가 경고를 내면, 총괄은 `반영`, `유예`, `기각` 중 하나로 판정한다.
- 훅이나 자동 실행이 결과를 만들었더라도 총괄 확인 전에는 캐논으로 취급하지 않는다.
- `Smoke FAIL`이면 push하지 않는다.
- lore/storycraft pass가 깨졌다면 다음 pass는 `repair pass`로 명시하고 다시 진입한다.
- 분량 미달은 `경고`가 아니라 **즉시 FAIL**이다.
- 분량 미달 화는 예외 없이 `repair pass`가 아니라 **재작성**으로 처리한다.

## 7. 런타임 금지 패턴

- 하네스를 돌리지 않고 장기 패스 커밋
- 전문가 의견을 검토 없이 캐논으로 승격
- 훅 결과를 곧바로 병합
- MCP에서 읽은 외부 정보를 기준 문서보다 앞에 두기
- `setting-first`가 켜진 상태에서 drafting lane 우회 개방
- 분량 미달 화를 임시 통과로 계산
- `REQUIRED_EXPERT_LOCK.md`에 없는 전문가를 상시 기본 전문가처럼 운용
