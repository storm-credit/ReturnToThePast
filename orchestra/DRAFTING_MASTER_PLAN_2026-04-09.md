# 집필 마스터 플랜 2026-04-09

날짜: `2026-04-09`
상태: `ACTIVE ON REQUEST`
총괄: `novel-orchestra-conductor`
기준 모드: `설정집 잠금 완료 -> 집필 -> 검수 -> 환류`

## 1. 목표

- `15권 x 권당 25화`를 RTTP 엔진 기준으로 연재 가능한 리듬으로 운영한다.
- 각 화는 공백 제외 `3,500자 이상`을 **절대 하한선**으로 잡는다.
- 분량 미달 화는 **무조건 재작성**하며, 진척으로 계산하지 않는다.
- 모든 초안은 하네스 검증을 거친 뒤에만 진척으로 계산한다.
- 설정집은 다시 처음부터 열지 않고, 집필 중 드러난 충돌만 좁게 환류한다.

## 2. 기본 운영 원칙

- 기본 cadence는 `주 4화`다.
- 여유가 생긴 주만 `주 5화`까지 확장한다.
- 권당 25화 기준으로 `약 5~6주/권`을 표준 리듬으로 본다.
- 미검증 초안은 진행으로 계산하지 않는다.
- `PASS한 배치`만 진척으로 계산한다.

## 3. 화 단위 실행 루프

각 화는 아래 순서로 고정한다.

1. `Launch Packet` 확인
2. 초안 작성
3. `공백 제외 글자수 체크`
4. `Chapter Audit`
5. `Smoke`
6. 병합 메모 기록

한 화가 끝날 때마다 아래를 확인한다.

- 그 화의 목표, 방해, 반전, 발견, 선택 중 최소 하나가 선명한가
- 공백 제외 `3,500자 이상`을 넘겼는가
- 인물 말투와 감정선이 설정집과 어긋나지 않는가
- 장소가 실제 압박으로 작동하는가
- 새 정보가 나왔을 때 누가 알고 누가 모르는지 유지되는가
- 끝문장이 다음 화 압력을 남기는가

## 4. 3화 배치 검증

`3화` 단위로 한 번씩 아래 순서로 배치 검증한다.

1. `Storycraft`
2. `Foreshadow`
3. `Lore`
4. `Smoke`

배치 검증에서 보는 핵심은 아래와 같다.

- 장면 압력과 감정 리듬이 계속 살아 있는가
- 복선이 장식이 아니라 오해, 불안, 질문으로 기능하는가
- 설정 충돌 없이 사건이 누적되는가
- 금지 표면어와 금지 서사가 다시 유입되지 않았는가

## 5. 5화 단위 검증

`5화`마다 권 내부 체크포인트를 돈다.

### 패러독스 체크

- 이번 구간 사건이 `고정점 / 분기점 / 압박 후폭풍` 중 어디에 속하는지 다시 확인
- 새 개입에 `대가 / 반작용 / 징후`가 바로 붙었는지 확인
- 독자가 `이상함`은 느끼되 `정답`을 너무 빨리 알지 않았는지 확인

### 인물/세력/배경 체크

- 에이든, 아이리스, 리아, 적대축 관계가 한 단계라도 이동했는지 확인
- 세력의 실무선과 내부 논리가 장면 안에 실제로 드러났는지 확인
- 새 권역이나 새 건물이 독자가 구조를 잡을 만큼 반복 노출되었는지 확인
- 진전이 있었다면 감정, 관계, 시간, 몸, 정보 중 하나의 비용이 남았는지 확인

## 6. 권 시작 전 체크

권에 들어가기 전 아래를 먼저 잠근다.

- 이번 권 핵심 사건의 태그: `고정점 / 분기점 / 압박 후폭풍`
- 주인공이 믿는 표면 서사와 실제 진실의 거리
- 이번 권의 `얻는 것 1개 / 잃는 것 1개`
- 이번 권이 후반 결말에 남기는 `빚 / 씨앗 / 오해 유도`
- Outline / Timeline / Mandatory Events / Foreshadow Ledger 동기화 여부

## 7. 권 종료 전 체크

- 이번 권에서 무엇이 바뀌었고 무엇이 못 바뀌었는지 정리
- 주역들의 상태가 권 초반과 비교해 분명히 달라졌는지 확인
- 이번 권에서 이긴 세력과 손해 본 세력이 정리되는지 확인
- 이번 권의 대가가 다음 권 감정선과 관계선에 실제 흔적으로 남는지 확인
- 다음 권 브리지가 자연스럽게 넘어가는지 확인

## 8. 커밋 / 푸시 리듬

### 중간 체크포인트

- 기준: `2화마다` 또는 `수요일 21:00 KST` 중 먼저 오는 시점
- 조건: `공백 제외 3,500자 이상 + Chapter Audit 통과 + Smoke PASS`

- 조건: `3~5화 배치 완료 + 전 화 분량 기준 충족 + Storycraft/Foreshadow/Lore/Smoke 순차 검증 완료`
- 동작: 주간 요약 커밋 + 푸시 + 다음 주 패킷 확정

### 커밋 원칙

- 커밋 단위는 `화 단위`보다 `검증 단위`로 묶는다
- 미검증 초안은 푸시하지 않는다
- `.obsidian`과 `orchestra/runs`는 기본 커밋 범위 밖에 둔다

## 9. fail-safe

- `Lore`나 `Foreshadow`에서 깨지면 다음 화로 넘어가지 않고 `repair sprint` 1회를 먼저 돈다
- 같은 종류의 충돌이 `2화 연속` 나오면 속도를 `주 4화 -> 주 3화`로 낮춘다
- 고정점 위반이 잡히면 그 화가 아니라 `해당 권 설계`까지 되돌린다
- 문체나 금지 표면 재오염은 즉시 `tone-guard-hook`과 `banned-surface-hook`으로 차단한다
- 분량 미달은 다른 결함보다 우선한다. 미달이 나오면 해당 화는 **즉시 재작성**하고 다음 화로 넘어가지 않는다.
