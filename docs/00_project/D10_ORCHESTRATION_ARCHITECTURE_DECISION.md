# D10 오케스트레이션 구조 결정

Status: SELECTED ARCHITECTURE  
Date: 2026-08-07  
Decision Owner: Author  
Prepared By: A00 Story Orchestrator / A02 Canon Controller / A16 Red Team

## 문제

현재 저장소에는 세계관·인물·기관·유산·미스터리·375화 설계 문서가 존재하지만 다음 문제가 남아 있었다.

1. `CLAUDE.md`가 부팅 안내서인지 최상위 정본인지 경계가 불명확했다.
2. 에이전트·스킬·정본·작법·하네스의 책임이 일부 중복됐다.
3. 회차 집필 전에 필요한 문서를 자동으로 묶는 Context Pack이 없었다.
4. 작법은 여러 문서에 흩어져 있었고 상황별 선택 규칙이 없었다.
5. 보조 POV와 주인공 부재 사건의 실제 배치·정당화가 부족했다.
6. 분야별 설정집의 깊이가 서로 달라도 원고 에이전트가 동일하게 READY로 오인할 수 있었다.

## 비교한 네 가지 방법

### 방법 1 — 단일 `CLAUDE.md` 중심형

구조:
- 모든 규칙·설정·에이전트·작법을 `CLAUDE.md`에 집중

장점:
- 진입점이 하나라 이해가 쉽다.
- 작은 프로젝트에서는 빠르다.

문제:
- 문서가 비대해지고 서로 다른 권한이 섞인다.
- `CLAUDE.md` 수정 한 번이 정본 전체 변경처럼 작동할 수 있다.
- 세부 설정과 작업절차가 뒤섞여 오래된 내용이 남기 쉽다.
- 작가 결정·정본 헌법·상태 장부보다 부팅 문서가 위에 서는 오류가 발생한다.

판정: REJECT

### 방법 2 — 분야별 에이전트 자치형

구조:
- 캐릭터·지리·종교·아이템·시간·플롯 에이전트가 각자 자기 문서를 소유
- 총괄은 결과만 병합

장점:
- 전문성이 분명하다.
- 분야별 확장이 쉽다.

문제:
- 캐릭터 에이전트가 플롯을, 플롯 에이전트가 세계관을 조용히 바꿀 위험이 있다.
- 동일 회차에 필요한 여러 분야의 사실을 누가 조합하는지 불명확하다.
- 에이전트 간 충돌 해결과 최신 상태 동기화 비용이 크다.
- 분야 문서가 많아도 원고가 실제로 읽지 않을 수 있다.

판정: PARTIAL USE ONLY

### 방법 3 — 스킬 중심 파이프라인형

구조:
- 작법, 낭독, 연속성, POV, 설정 호출을 모두 스킬로 구현
- 파이프라인이 스킬을 순차 실행

장점:
- 절차 재사용이 쉽다.
- 검사 항목을 자동화하기 좋다.

문제:
- 스킬은 절차이지 정본의 소유자나 승인자가 아니다.
- 서로 다른 스킬이 상충하는 판단을 했을 때 최종 책임자가 없다.
- 서사 판단까지 체크리스트화하면 작품이 기계적으로 변할 수 있다.
- 분야별 설정의 권한과 변경 책임을 설명하지 못한다.

판정: SUPPORTING LAYER ONLY

### 방법 4 — 정본 우선 계층형 오케스트라

구조:

1. 작가 결정
2. 정본 헌법·개정안·Decision Log
3. 현재 상태 장부
4. 분야별 Bible
5. 시리즈·권·Arc·Subact·회차 설계도
6. 회차 Context Pack
7. 상황별 작법 스킬
8. 원고 작성
9. 다중 감사·상태 갱신·GitHub 병합

장점:
- 권한과 실행을 분리한다.
- `CLAUDE.md`는 얇은 라우터로만 유지된다.
- 에이전트는 판단·승인·책임을 맡고, 스킬은 반복 절차를 맡는다.
- CP가 각 회차에 필요한 정본만 정확히 묶어 컨텍스트 누락과 과부하를 줄인다.
- 훅과 하네스가 누락·조용한 변경·연속성 오류를 자동 차단한다.
- 캐릭터·종교·아이템 등 세부 문서가 실제 원고에 사용됐는지 추적할 수 있다.

문제:
- 초기 설계가 복잡하다.
- CP 생성과 상태 장부 갱신이 추가로 필요하다.

판정: SELECTED

## 최종 선택

**방법 4 — 정본 우선 계층형 오케스트라**를 채택한다.

방법 2의 전문 에이전트와 방법 3의 반복 스킬은 방법 4 안의 하위 구성요소로 사용한다.

## 권한 계층

충돌 시 다음 순서를 따른다.

0. 작가의 최신 명시 결정
1. `docs/00_project/canon-constitution-v1.md`
2. 승인된 Canon Amendment / Errata
3. `docs/00_project/decision-log.md`
4. 시간선·인물·기관·자산·미스터리·손실 상태 장부
5. 분야별 World/System/Character/Faction/Institution/Collection Bible
6. Grand Act·Volume·Arc·Subact·Episode Architecture
7. Craft Overlay·POV Allocation·Context Pack
8. 원고 및 품질보고서
9. Legacy Drafts

`CLAUDE.md`는 위 계층에 포함되지 않는다. 그것은 부팅·탐색·라우팅 문서이며 독립적인 정본 권한이 없다.

## 구성요소 구분

### 에이전트
판단, 승인, 책임, 분야 소유권을 갖는다.

### 스킬
반복 가능한 작업방법과 검사 절차를 제공한다. 정본을 단독 승인하지 못한다.

### CP — Context Pack
특정 작업에 필요한 정본의 출처·현재값·금지선·상태를 모은 읽기 전용 묶음이다. 새로운 정본이 아니다.

### MCP
Model Context Protocol을 뜻하는 경우 GitHub·파일·외부 도구 연결에만 사용한다. 작품 설정을 MCP 서버의 숨은 상태에 저장하지 않는다. 정본은 항상 저장소 문서에 남긴다.

### Hook
필수 파일 누락, 정본 충돌, 미승인 설정 변경, 상태 장부 미갱신을 자동 차단하는 조건이다.

### Harness
에이전트·스킬·CP·Hook을 어떤 순서로 실행할지 정의하는 전체 작업 흐름이다.
