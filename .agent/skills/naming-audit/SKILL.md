# Korean Webnovel Fantasy Naming Audit

## 1. 목적

이 스킬은 이름을 많이 만드는 도구가 아니다.

다음 문제를 차단한다.

- 뜻을 해독해야 하는 AI식 조어
- 현대 행정·SF 용어에 판타지 접두어만 붙인 이름
- 모든 일반 사물을 고유명사로 만드는 과잉 설정
- 라틴·그리스·북유럽 어감을 근거 없이 섞는 명명
- 유명 신화·게임·소설 고유명사의 직접 차용
- 정본 이름을 영향 분석 없이 일괄 치환하는 작업

기준 문서:

`docs/13_writing_harness/korean-webnovel-fantasy-naming-rules-v1.md`

## 2. 실행 조건

다음 요청에서 실행한다.

- 새 인물·국가·도시·기관·종교·직업·장비·현상 이름 생성
- 기존 이름이 어색한지 검수
- 한국 웹소설 판타지 톤으로 명칭 정리
- 라틴·그리스로마·북유럽식 이름 적용 검토
- 원고의 현대식 장비명·행정용어 검수
- 저장소 전체의 명칭 일괄 변경 전 영향 분석

단순 오탈자 교정에는 실행하지 않는다.

## 3. 권한 확인

A00이 작업을 다음 중 하나로 분류한다.

1. **표현 교정** — 정본 사실은 유지하고 원고 속 일반 표현만 다듬음
2. **신규 명명** — 아직 정본명이 없는 대상에 후보 제시
3. **정본 개명** — 현재 정본 또는 SOFT/HARD LOCK 이름 변경

정본 개명은 A02 확인과 작가의 명시 승인이 없으면 후보 검토까지만 진행한다.

## 4. 담당 에이전트

### 필수

- A00 Story Orchestrator
- A02 Canon Controller
- A15 Similarity Audit
- A19 Sentence Narration & Korean Prose Audit
- A16 Red Team
- A17 GitHub State Verifier

### 대상별 Domain

- A03: 국가·도시·지역·지형
- A04: 마법·질병·치료·마도장비
- A05: 언어·종족·종교·신화·의례
- A06: 왕실·기관·법·직업·계급
- A07: 시간여행·기억·귀환·시간현상
- A10: 장비·유물·문서·소유권
- A13: 일괄 개명 시 연속성·참조 누락

A20은 장르 약속이나 독자 정보량에 영향이 있을 때만 보조로 호출한다.

## 5. 입력

작업 전에 다음을 확보한다.

- 대상의 ID 또는 명확한 기능
- 대상이 속한 국가·지역·시대·문화
- 현재 이름과 잠금 상태
- 기존 사용 파일과 첫 등장 원고
- 독자가 처음 알아야 할 기능
- 이름이 실제 대사에서 불리는 방식
- 참고하려는 어감 계열

정보가 없으면 이름부터 만들지 않는다.

## 6. 실행 절차

### Step 1. 저장소 검색

현재 이름, 별칭, 역할명, 이전 작업명을 전체 검색한다.

다음을 구분한다.

- Canon Constitution / Amendment / Decision Log
- Domain Bible
- Story Architecture
- Context Pack
- Manuscript
- Legacy

원고에만 있는 이름을 정본으로 오인하지 않는다.

### Step 2. 이름 필요성 판정

다음 질문에 답한다.

- 이 대상은 반복 등장하는가
- 다른 대상과 구별할 고유 정체성이 필요한가
- 독자가 이름을 기억해야 다음 장면을 이해하는가
- 일반명이나 행동 묘사로 충분하지 않은가

필요성이 낮으면 새 이름을 만들지 않는다.

### Step 3. 문화권 음운 확인

문화권마다 다음을 정한다.

- 참고 어감 계열
- 허용 음절과 이름 길이
- 개인명·가문명·지명 구조
- 직함의 위치
- 금지할 혼합 계열

실제 언어의 정확한 재현을 주장하지 않는다.

### Step 4. 후보 생성

후보는 최대 4개만 만든다.

각 후보에는 다음을 붙인다.

- 발음
- 대상 분류
- 독자가 처음 받는 인상
- 기능 추정 가능성
- 같은 문화권 이름과의 일관성
- 직접 연상 위험

후보 수를 채우기 위해 약한 이름을 만들지 않는다.

### Step 5. 문장 삽입 검사

각 후보를 최소 3가지 문장에 넣는다.

- 공식 서술
- 현장 대사
- 일상적 축약 호칭

조사와 붙였을 때 어색하면 탈락시킨다.

### Step 6. 7단계 감사

- 첫 청취
- 기능 추정
- 대사 삽입
- 장르 적합
- 과잉 조어
- 문화 일관성
- 유사성

한 항목이라도 S1이면 정본 후보로 제시하지 않는다.

### Step 7. 변경 영향표

기존 이름 변경 시 다음을 검색한다.

- 정본 문서
- 원고
- 설계도
- CP
- 발음사전
- 검증기
- 품질보고서
- 상태장부

문자열 치환으로 인과·직함·시대·동명이인을 바꾸지 않는다.

### Step 8. 작가 승인

후보와 영향표를 먼저 제시한다.

작가 승인 전에는:

- 정본 이름 확정 금지
- 원고 일괄 치환 금지
- HUMAN PROSE PASS 금지
- main 병합 금지

## 7. 라틴·그리스·북유럽 어감 검사

### 라틴 계열

왕실·법·제국·학술·수도권에 적합할 수 있다. 실제 라틴어를 길게 복사하거나 모든 이름을 같은 어미로 끝내지 않는다.

### 그리스·그리스로마 계열

신전·별·예언·의술·고대 유적에 적합할 수 있다. 유명 신·영웅·저승·유물 이름을 그대로 쓰지 않는다.

### 북유럽 계열

북부 변경·전사 가문·항해·룬 문화에 적합할 수 있다. 유명 신화 고유명사와 `-손` 남용을 금지한다.

### 혼합 규칙

한 문화권에서 여러 계열을 섞으려면 작품 내부의 정복·이주·종교전파·혼혈·언어층 같은 역사적 이유가 있어야 한다.

## 8. AI 조어 경보

다음 중 2개 이상이면 S1 후보로 분류한다.

- 추상 한자어 3개 이상 결합
- 기능을 전부 이름에 넣음
- `시공·연대·잔흔·각인·성력·마도·결계` 중 하나를 분위기용으로 부착
- 일반 사물을 고유명사화
- 첫 등장에 별도 설명문이 필요
- 실제 인물이 대사에서 부르기 어려움
- 기존 문화권 이름과 음운이 다름
- 유명 작품의 용어가 먼저 떠오름

## 9. 출력 형식

### 검수

`위치 / 기존 명칭 또는 문장 / 문제점 / 담당 Agent / 심각도 / 교체 원칙 / 후보 최대 4개 / 정본 변경 필요 여부`

### 신규 명명

`대상 / 기능 / 문화권 / 참고 어감 / 후보 / 발음 / 장점 / 위험 / 추천 순위`

### 정본 개명

- 현재 잠금 상태
- 권위 출처
- 변경 대상
- 변경 이유
- 후보 비교
- 전체 영향 파일
- 필요한 Amendment/Decision Log
- 작가 승인 상태
- 병합 가능 여부

## 10. 판정

- `PASS`: 이름이 자연스럽고 정본·문화·장르·낭독 검사를 모두 통과
- `REVISE`: 후보는 가능하지만 발음·기능·문화 일관성 수정 필요
- `BLOCK`: 작가 승인 없는 정본 개명, 직접 차용, AI 조어, 문화 혼합, 영향 누락

이 스킬은 이름 후보를 제시할 수 있지만 정본을 단독 승인하지 않는다.
